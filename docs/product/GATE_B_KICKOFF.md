# Gate B: 週次利用（4週間）キックオフ

作成日: 2026-06-13
判定対象: ROADMAP §10 Gate B「4週間の実利用で、記録漏れ・二重入力・操作停滞を観察する。
問題が残る場合、分析・AI へ進まない」／ Phase 1 出口条件「Jimi が4週連続で Spreadsheet と
併用せず、次の主日の計画を Keryx Next で更新できる」。

Gate B は実装ゲートではなく **実利用の観察期間**。Jimi が4週間、毎週 Keryx だけで次の主日を
計画・準備する。本書はその準備（アプリ側の整え）と、観察の記録方法をまとめる。

## 1. 観察する3つの失敗モード

| 観点     | 何を見るか                                     | アプリ側の支え                                               |
| -------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 記録漏れ | 入れ忘れ（箇所・メッセージ・予定）が起きないか | ホーム「要確認」が未割り当て/箇所未入力/準備遅延を表示       |
| 二重入力 | 同じ情報を二度入れていないか                   | 取り込みの冪等判定、「別の場所でも語る（複製）」、複製ボタン |
| 操作停滞 | 週次の流れがどこかで詰まらないか               | Quick Add（＋FAB）、新規作成→詳細集中入力、検索              |

## 2. 週次ワークフロー（毎週これで回す）

1. **ホームを開く** → 次の集会・要確認・今後4週間を確認。
2. 次の主日が未登録なら **＋（FAB）** か メッセージ「新規作成」→ 詳細で 題・聖書箇所・
   語る機会（日時・会場）を入力。
3. **準備段階**を進める（未着手→釈義→アウトライン→原稿→完了）。
4. 同じ説教を別の場所でも語るなら、詳細の **「別の場所でも語る（複製）」**。
5. 必要に応じて **カレンダー**（教会暦つき）・**検索**・**分析**で振り返り。
6. 週末に **ホーム「要確認」が空**になっていれば、その週は記録漏れなし。

## 3. すでに整っている機能（Gate B 時点）

- 認証・Workspace（個人）、メッセージ/シリーズ/礼拝予定/礼拝順序、準備段階、ホーム・カレンダー。
- ホーム「要確認」（未割り当て・聖書箇所未入力・準備遅延）。
- 取り込み（Dry Run＋本取り込み・冪等）、検索＋保存フィルタ、基本分析、教会暦、履歴と復元。
- エクスポート（JSON/CSV/Markdown）、PWA（インストール・オフライン表示）。

## 4. 観察ログ（4週間、気づいたら追記する）

```
週 / 日付 | 観点(記録漏れ/二重入力/操作停滞) | 状況・引っかかり | 重大度 | メモ
W1 ____  |                                 |                  |        |
W2 ____  |                                 |                  |        |
W3 ____  |                                 |                  |        |
W4 ____  |                                 |                  |        |
```

> 小さな引っかかりでも記録する価値がある。詰まった画面・遷移・言葉づかい・足りない項目など。

## 5. 出口条件 / 判定

- 4週連続で Spreadsheet と併用せず、次の主日を Keryx で計画・更新できた。
- 記録漏れ・二重入力・操作停滞のうち、運用を妨げる重大なものが残っていない。
- 保存失敗・データ消失がゼロ。

満たせば Phase 3（分析の拡充）・将来の AI へ。残課題があれば、分析・AI に進む前に先に直す。

## 6. 補足

- 観察で出た改善は小さな垂直スライスで対応する（このリポジトリの方針どおり）。
- 週次の振り返りは `/schedule` で定期チェックを設定できる（任意）。
