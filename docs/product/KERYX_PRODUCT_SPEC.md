# Keryx Next プロダクト仕様書

バージョン: Draft 1.0  
更新日: 2026-06-11  
プロダクトオーナー: Jimi

## 1. プロダクトビジョン

Keryx Next は、牧師が「次の主日に何を語るか」だけでなく、「一年を通して何を、どこで、どのように語ってきたか」を見渡し、礼拝と説教準備に集中できる説教管理ワークスペースである。

スプレッドシートの自由さ、カレンダーの見通し、専門的な説教管理の構造、静かで使いやすい執筆環境を一つに統合する。

### 中心価値

> 計画を見渡し、準備を進め、説教の歩みを振り返る。

### 成功した状態

- 牧師が30秒以内に次の説教と準備状況を把握できる。
- 2分以内に新しい説教・祈祷会奨励・礼拝予定を登録できる。
- 年間の説教箇所、旧約・新約、書巻ジャンル、テーマの偏りを視覚的に確認できる。
- 礼拝順序や式典が柔軟に扱え、固定列を追加し続ける必要がない。
- データが安全に保存され、Sheets へのエクスポートも可能で、ユーザーが囲い込まれない。

## 2. 対象ユーザー

### 第一ペルソナ: 個人で計画する牧師

- 一人または少人数で説教計画を管理する。
- 連続講解を中心に、教会暦・特別礼拝・祈祷会も扱う。
- 現在はノート、カレンダー、スプレッドシート、執筆アプリが分散している。
- 高機能さよりも「毎週迷わず使えること」を重視する。

### 第二ペルソナ: 教会チーム

- 主任牧師、協力牧師、奏楽者、司会者、事務担当者が計画を共有する。
- 説教内容の機密性と、礼拝予定の共有範囲を分けたい。
- 誰が何を更新したか確認したい。

### 将来ペルソナ

- 複数教会・複数会場を巡回する説教者
- 神学校教員・チャペル担当者
- 教派・団体の礼拝計画担当者

## 3. Jobs To Be Done

1. 次の主日と数週間先の準備状況を、アプリを開いた瞬間に把握したい。
2. 思いついた説教候補をすぐ Inbox に記録し、後で日程・シリーズへ割り当てたい。
3. 一つの説教を複数の日時・会場で語った履歴を残したい。
4. 招詞、賛美、交読、式典などを礼拝ごとに柔軟に並べたい。
5. 年間計画をカレンダーと一覧の両方で編集したい。
6. 説教箇所・テーマ・書巻・旧新約の偏りを振り返りたい。
7. Spreadsheet 版の既存データを失わず移行したい。

## 4. プロダクト原則

### 4.1 牧会のための静かな道具

画面は情報量を持ちながらも、一般的な営業管理ツールのような騒がしさを避ける。温かい紙面感、明確な階層、落ち着いた色、十分な余白を使う。

### 4.2 速い入力、深い構造

初回入力では最低限の情報だけで保存できる。一方、後から礼拝順序・テーマ・準備タスク・複数会場などを詳細に構造化できる。

### 4.3 一つの事実を一度だけ保存

説教内容、礼拝機会、聖書箇所、シリーズ、会場、礼拝要素を分離し、同じ情報の重複入力を避ける。

### 4.4 日本語ファースト

日本語の聖書書名・略称・入力習慣・教会用語を第一に設計する。英語対応は可能にするが、日本語を翻訳版として扱わない。

### 4.5 AI は助手であり権威ではない

AI は整理・候補提示・分類・要約を支援する。聖書本文、釈義、神学判断を捏造・断定せず、生成結果はユーザーが確認して初めて正本になる。

### 4.6 ユーザーのデータはユーザーのもの

CSV、JSON、Markdown でのエクスポートを提供する。削除・バックアップ・履歴を明確にする。

## 5. 情報モデル

### 5.1 核心概念

| 概念             | 説明                                 | 例                                       |
| ---------------- | ------------------------------------ | ---------------------------------------- |
| Workspace        | 個人または教会チームのデータ境界     | Jimi 個人、永福南キリスト教会            |
| Message          | 語る内容。説教、祈祷会奨励、講演など | 「恐れるな、わたしはあなたとともにいる」 |
| Gathering        | 実際の日時・会場・集会               | 2026-06-14 主日礼拝                      |
| Message Delivery | Message と Gathering の関連          | 同じ説教を本教会と別会場で語る           |
| Service Element  | 礼拝内の順序を持つ要素               | 招詞、開会賛美、説教、聖餐式、頌栄       |
| Series           | 複数 Message をまとめる計画          | 創世記連続講解                           |
| Passage          | 構造化された聖書範囲                 | ヨハネ3:16-21                            |
| Preparation Task | 説教準備の作業と進捗                 | 釈義、骨子、原稿、推敲、投影資料         |
| Observance       | 教会暦・特別行事                     | アドベント第1主日、召天者記念礼拝        |
| Theme            | 分析・検索用テーマ                   | 恵み、契約、祈り                         |

### 5.2 Message と Gathering を分離する理由

- 説教日は「説教そのもの」の属性ではなく、「語った機会」の属性である。
- 同じ説教を複数回語っても原稿・命題・聖書箇所を重複保存しなくてよい。
- 祈祷会奨励、主日説教、特別集会を同じ基盤で扱える。
- 礼拝担当者には Gathering と礼拝順序だけを共有し、非公開の説教ノートは共有しない権限設計が可能になる。

## 6. 機能要件

優先度は `P0` 必須、`P1` 初期リリース後すぐ、`P2` 成長機能、`P3` 将来構想を表す。

### 6.1 ダッシュボード

#### P0

- 次の Gathering を大きく表示する。
- Message タイトル、聖書箇所、シリーズ、会場、説教者、残り日数を表示する。
- 準備進捗を段階別に表示する。
- ダッシュボードから Message または Gathering を素早く作成できる。
- 今後4〜8週間の予定をタイムライン表示する。
- 未確定・準備遅延・聖書箇所未入力など、要確認項目を表示する。

#### P1

- 年間の旧約・新約比率、書巻ジャンル、シリーズ、テーマ上位、未使用書巻を可視化する。
- 集計期間、説教者、会場、集会種別で絞り込める。
- ダッシュボードカードを並べ替え・表示切替できる。

### 6.2 Message 管理

#### P0

- Message 種別: `sermon`、`prayer_meeting_exhortation`、`devotional`、`lecture`、`other`。
- タイトル、中心メッセージ、概要、アウトライン、ノートを保存できる。
- 状態: Inbox、計画中、準備中、準備完了、完了、アーカイブ。
- シリーズ、聖書箇所、テーマ、タグを関連付けられる。
- 一覧・カード・詳細画面から作成、編集、複製、アーカイブ、削除できる。
- 人間向け表示 ID は自動生成し、ユーザー入力を求めない。
- 変更途中の自動保存または明確な未保存表示を提供する。

#### P1

- 添付ファイルと外部リンクを保存する。
- Markdown エクスポートと印刷向け表示を提供する。
- Scrivener、Obsidian、Google Docs へのリンクを保持する。
- 過去に同じ・近接する聖書箇所を扱った Message を表示する。

### 6.3 Gathering と礼拝計画

#### P0

- 日時、タイムゾーン、会場、集会種別、説教者、担当者を設定できる。
- Gathering に Message を割り当てられる。
- 一つの Message を複数 Gathering に割り当てられる。
- 礼拝順序を並べ替え可能な要素として管理する。
- 標準要素として、招詞、開会賛美、祈り、聖書交読、聖書朗読、説教、応答賛美、献金、式典、頌栄、祝祷を用意する。
- 任意の要素タイプを追加・削除できる。
- 賛美と式典を複数追加できる。式典の前後にも賛美を自由に配置できる。
- 式典タイプとして、聖餐式、洗礼式、転入会式、任職式、召天者記念、その他を用意する。
- よく使う礼拝順序をテンプレート保存できる。

#### P1

- 礼拝順序だけを共有・印刷・PDF 出力できる。
- 担当者へ閲覧・確認依頼を送れる。
- Gathering ごとの実施メモと振り返りを保存できる。

### 6.4 聖書箇所入力

#### P0

- 日本語書名・一般的略称・英語名から書巻を検索できる。
- 書巻、開始章節、終了章節を選択できる。
- `ヨハネ3:16-21`、`ヨハ 3:16–21`、`John 3:16-21` などを解析できる。
- 一つの Message に複数 Passage を追加できる。
- 主たる箇所と補助箇所を区別できる。
- 表示文字列とは別に、canon、testament、book、chapter、verse を構造化保存する。
- 無効な章節や逆転範囲を検証する。

#### P1

- Passage 入力時に過去の使用回数と直近使用日を表示する。
- 書巻・章ごとの説教カバレッジマップを表示する。
- 初期版では著作権保護された聖書本文を保存・再配布しない。

### 6.5 シリーズ管理

#### P0

- シリーズ名、説明、色、期間、書巻、目標、状態を管理できる。
- シリーズ内 Message を並べ替えられる。
- 連続講解の次候補箇所を手動で計画できる。
- シリーズ詳細から欠けている日程・Message を確認できる。

#### P1

- シリーズ計画と実績の差を表示する。
- 途中休止、特別礼拝挿入、再開を自然に扱う。

### 6.6 カレンダーと教会暦

#### P0

- 月、週、年間のカレンダー表示を提供する。
- カレンダーから Gathering を作成・移動できる。
- 日本の祝日と、選択した教会暦プリセットを重ねて表示できる。
- アドベント、クリスマス、年末・年始、受難週、イースター、ペンテコステ、召天者記念、伝道礼拝などを扱う。
- Observance は教派・教会ごとに有効化、名称変更、独自追加できる。
- シリーズと Observance を混同しない。

#### P1

- iCal 購読またはエクスポート。
- 複数会場・説教者を色分け。
- 毎週・毎月などの繰り返し Gathering 作成。

### 6.7 準備ワークフロー

#### P0

- テンプレート化された準備タスクを Message ごとに生成する。
- 初期テンプレート: 本文確定、文脈、原語、構文・文法、背景、神学的主題、キリストへの照準、適用、骨子、原稿、推敲、資料。
- 各タスクに状態、期限、メモを設定できる。
- Message 全体の進捗率を表示する。
- 期限超過と次に行う作業をダッシュボードに表示する。

#### P1

- Message 種別ごとに準備テンプレートを設定できる。
- チェックリストを複製・並べ替えできる。
- リマインダーを設定できる。

### 6.8 検索・フィルター・分析

#### P0

- タイトル、中心メッセージ、聖書箇所、シリーズ、テーマ、会場、説教者、日付で検索できる。
- フィルターを保存できる。
- 旧約・新約、書巻、ジャンル、Message 種別、状態を集計できる。
- 新約ジャンルでは「一般書簡」ではなく「公同書簡」を使用する。

#### P1

- テーマ分布、時系列、説教箇所の重複、書巻カバレッジを可視化する。
- 集計グラフから該当 Message 一覧へドリルダウンできる。
- 分析結果には件数と集計条件を明示する。

### 6.9 インポート・エクスポート

#### P0

- Keryx Spreadsheet v1.3.1 の台帳を CSV/XLSX からインポートする。
- インポート前にプレビュー、列対応、検証エラー、重複候補を表示する。
- ID は移行時に自動発行する。
- Message、Gathering、Service Element への分割結果を確認できる。
- CSV、JSON、Markdown でエクスポートできる。

#### P1

- 定期バックアップをダウンロードできる。
- Google Sheets との一方向エクスポートを提供する。

### 6.10 チームと権限

#### P1

- Workspace へメンバーを招待できる。
- ロール: Owner、Pastor、Planner、Viewer。
- 説教ノートの閲覧権限と礼拝計画の閲覧権限を分離できる。
- 重要操作の監査履歴を表示する。

### 6.11 AI 支援

#### P2

- ユーザーが入力した内容をもとに、テーマ候補、タグ候補、要約候補を提示する。
- 年間計画の偏りや重複を説明付きで指摘する。
- 過去の本人の Message から関連候補を検索する。
- 礼拝要素の未入力候補を提示する。
- AI 提案は明確に区別し、ユーザー承認なしに正本へ書き込まない。
- 引用・聖書本文・出典を捏造しない。確証がなければ不確実と表示する。

#### 非目標

- 初期版で説教原稿を全自動生成すること。
- AI に神学的最終判断を委ねること。
- ユーザーの機密ノートを無断でモデル学習へ利用すること。

## 8. 主要ユーザーフロー

### 8.1 30秒 Quick Add

1. どの画面からでも `N` または Quick Add を開く。
2. Message 種別、仮タイトルまたは聖書箇所を入力する。
3. 日付未定なら Inbox、日付指定なら Gathering も同時作成する。
4. 保存後、次の入力候補としてシリーズ・会場・テンプレートを提示する。

### 8.2 主日礼拝を計画する

1. カレンダーの日付から Gathering を作成する。
2. 主日礼拝テンプレートを適用する。
3. 新規または既存 Message を割り当てる。
4. 招詞、賛美、交読、式典などを入力・並べ替える。
5. 準備テンプレートを生成し、期限を自動提案する。

### 8.3 同じ説教を別会場で語る

1. Message 詳細から「語る機会を追加」を選ぶ。
2. 日時、Venue、集会種別、対象会衆を設定する。
3. 必要ならその Gathering 専用のメモを追加する。
4. Message 本文は共有し、実施履歴は別々に残す。

### 8.4 Spreadsheet から移行する

1. XLSX/CSV をアップロードする。
2. シートとヘッダーを自動認識し、列対応を確認する。
3. 日付・Passage・種別・礼拝要素を検証する。
4. 重複候補とエラーを修正する。
5. Dry Run の件数を確認してインポートする。
6. 移行レポートをダウンロードする。

## 9. デザイン仕様

### 9.1 デザイン人格

`calm / pastoral / scholarly / trustworthy / focused`

- 温かいオフホワイトと深い藍色を基調にする。
- アクセントは典礼色を使えるが、意味を色だけに依存しない。
- 説教準備画面は紙面のように静かに、ダッシュボードは視線誘導を明確にする。
- 高密度テーブルは必要な場面で提供するが、既定画面を管理台帳のようにしない。

### 9.2 インタラクション

- キーボード操作を第一級に扱う。
- Quick Add、Command Palette、Undo、明確な保存状態を提供する。
- ドラッグ操作にはキーボード代替を用意する。
- 削除は原則ソフトデリートとし、復元期間を設ける。
- 空状態には次の操作を一つ明示する。

### 9.3 アクセシビリティ

- WCAG 2.2 AA を目標とする。
- 文字サイズ、コントラスト、フォーカスリング、スクリーンリーダー名を検証する。
- 色覚に依存しない状態表示を行う。
- 日本語入力中の Enter キーで誤送信しない。

### 9.4 レスポンシブ方針

- Web はモバイルファーストだが、PC の広い画面では計画・比較・編集能力を高める。
- まず PWA とレスポンシブ Web を完成させ、ネイティブ iOS は利用実績に基づき実装する。

## 10. 非機能要件

### 性能

- 認証済みホームの主要情報を通常回線で2秒以内に表示する。
- Quick Add の保存結果を1秒以内にフィードバックする。
- 一覧は仮想化またはページングし、10,000 Message でも利用可能にする。

### 信頼性

- 重要な作成・更新には監査記録を残す。
- 競合更新を検知し、黙って上書きしない。
- インポートは再実行可能で、部分失敗を報告する。
- バックアップと復元手順を文書化する。

### セキュリティ・プライバシー

- 公開スキーマの全テーブルで RLS を有効化する。
- クライアントから service role key を使用しない。
- AI API キーをブラウザやユーザーメタデータへ平文保存しない。
- AI 呼び出しはサーバー経由とし、監査・レート制限・費用上限を設ける。
- Workspace 間のデータ漏えいを RLS テストで防ぐ。
- ログに説教本文、認証情報、秘密鍵を記録しない。

### ローカライゼーション

- 初期言語は日本語。
- 日付・曜日・タイムゾーンは `Asia/Tokyo` を既定とし、Workspace で変更可能にする。
- 文言をコンポーネントへ直書きせず、将来の英語化に備える。

## 11. 課金案

価格は検証前の仮説であり、実装より先に顧客インタビューで確認する。

| プラン    | 対象       | 仮の提供範囲                                       |
| --------- | ---------- | -------------------------------------------------- |
| Free      | 試用       | Message 件数制限、基本カレンダー、基本エクスポート |
| Personal  | 個人牧師   | 無制限 Message、分析、テンプレート、バックアップ   |
| Church    | 教会チーム | 複数メンバー、権限、共有、監査履歴                 |

## 12. 成功指標

### North Star

- 週に1回以上、次の Gathering の準備状態を更新したアクティブ Workspace 数。

### 活性化

- 登録後24時間以内に最初の Message と Gathering を作成した割合。
- Spreadsheet インポート完了率。
- 初回作成から礼拝テンプレート適用までの所要時間。

### 継続

- 4週、8週、12週継続率。
- 1 Workspace あたりの週次準備タスク更新数。
- 翌月以降の Gathering が計画されている割合。

### 品質

- 保存失敗率、インポート失敗率、RLS 障害件数。
- ユーザーが報告したデータ消失件数は常に0を目標とする。

## 13. 初期リリースの受け入れ条件

以下をすべて満たして初めて「Web MVP 完了」とする。

1. ユーザーがログインし、自分の Workspace だけを閲覧できる。
2. Message を作成し、構造化 Passage、シリーズ、テーマを保存できる。
3. Gathering を作成し、Message、Venue、説教者を割り当てられる。
4. 礼拝要素を自由に追加・削除・並べ替えでき、賛美を複数登録できる。
5. 説教準備タスクと進捗がホームに反映される。
6. 月間カレンダーに Gathering と Observance が表示される。
7. Spreadsheet v1.3.1 の代表データを Dry Run と検証付きで移行できる。
8. 旧約・新約、書巻ジャンル、公同書簡を含む基本分析が正しく表示される。
9. CSV/JSON/Markdown のエクスポートができる。
10. RLS、主要ユーザーフロー、アクセシビリティの自動テストが通る。

## 14. 初期版の非目標

- フル機能の説教原稿エディタで Scrivener や Obsidian を置き換えること。
- 聖書本文・注解書の再配布。
- 教会会計、会員管理、献金管理。
- 初期リリースでのネイティブ iOS アプリ。
- AI による説教の無確認自動生成・自動公開。
